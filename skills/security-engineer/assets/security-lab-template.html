01 · finite fields → ECC

A curve is a group, not a drawing.

Over a prime field, division means multiplication by an inverse. Curve points plus the point at infinity form an abelian group; scalar multiplication is repeated group addition.

Fp: a / b = a · bp−2 (mod p)
E: y² = x³ + ax + b (mod p)
Q = dG

The real security question is not “can I draw the curve?” It is whether a reviewed curve, subgroup, encoding, and implementation make recovering d from G and Q infeasible.

Validation is part of the primitive boundary. Reject invalid encodings, the point at infinity, off-curve points, and inappropriate subgroup/order cases before using a peer key.

Toy curve explorer

y²=x³+2x+2 mod 17

Public base G=(5,1), group order 19. Tiny enough to brute-force—never a production curve.

03 · ECDSA

The nonce is private-key material.

A signature proves knowledge of the private key for one encoded message. It does not encrypt, establish identity by itself, or forgive a weak nonce generator.

R = kG; r = x(R) mod n
s = k⁻¹(z + rd) mod n

reuse: k = (z₁−z₂)(s₁−s₂)⁻¹ mod n
d = (s₁k−z₁)r⁻¹ mod n

Real verification also rejects out-of-range values, validates the public key, follows the required message encoding and hashing rules, and obtains the public key through a trusted path.

Catastrophic failure: reuse, bias, leakage, or faulting of k can expose d. Deterministic nonce generation helps with RNG failures but does not remove constant-time and fault-resistance requirements.

04 · OpenSSL + KMS

APIs and operations are part of the proof.

Use reviewed high-level crypto APIs, then design the key lifecycle and outage path around them.

OpenSSL 3.x

Stay at the EVP/provider layer

EVP_DigestSign* / EVP_DigestVerify* for signatures, EVP_PKEY_derive* for ECDH, EVP_KDF_derive for HKDF, and EVP_PKEY_encapsulate* / decapsulate* for KEMs.

Pin the deployed version and provider policy, validate peers, check every result, size outputs according to the API, and clear sensitive buffers. OpenSSL 3.5 introduced native ML-KEM support.

Key lifecycle

Ask the questions APIs cannot answer

Who can create, use, export, rotate, disable, schedule deletion, audit, and recover each key? What plaintext exists during use? What happens if KMS is slow, unavailable, throttled, compromised, or regionally isolated?

A KMS narrows and observes key use. It does not make a compromised caller honest.

Randomness vocabulary

OpenSSL includes a CSPRNG; it is not the entropy source

OS entropy / TRNG provides unpredictable seed input. A DRBG expands and periodically reseeds internal state. OpenSSL's RAND_bytes and RAND_priv_bytes are application-facing APIs over that machinery.

On mainstream systems OpenSSL seeds from the operating system. Check the return code: seeding failure must become operation failure, never weak output.

06 · X.509 identity

A certificate can use ECDSA. X.509 is not ECDSA.

The container, subject public-key algorithm, and CA signature algorithm are separate choices.

Certificate = TBSCertificate + signatureAlgorithm + signatureValue

SPKI algorithm: id-ecPublicKey + named curve
CA signature: ecdsa-with-SHA256 (one possible choice)

An EC leaf public key may be signed by an ECDSA CA, an RSA CA, or another supported CA key. Likewise, an RSA leaf can sit below an EC intermediate. The verifier follows each certificate’s declared algorithms and local policy.

Path validation is a policy computation. Verify signatures, trust anchor, issuer linkage, basic constraints, path length, key usage/EKU, names, critical extensions, algorithm policy, time model, and revocation or pinning. A certificate is not a secret and possession must still be proven.

07 · Android StrongBox

Count blobs, trusted metadata, and evidence separately.

StrongBox is a dedicated secure processor profile, not a standardized flash capacity. Capacity and blob format are implementation-specific.

What Android specifies

Keys are represented by protected blobs

KeyMint returns generated/imported material as an encrypted, authenticated key blob. Android Keystore can store that blob outside the secure processor without learning the raw secret; the secure hardware validates authorizations when the key is used.

Rollback-resistant deletion may need additional replay-protected trusted metadata. That store can fill even when ordinary filesystem space remains.

What you must measure

No universal bytes-per-key quota

Measure the returned blob and Keystore database growth on every target device/OS combination. Separately load-test maximum keys, rollback-resistant keys, operation slots, latency, attestation chains, deletion, upgrade, and factory reset.

Use FEATURE_STRONGBOX_KEYSTORE and handle StrongBoxUnavailableException; StrongBox supports fewer algorithms and concurrent operations than a general TEE-backed implementation.

StrongBox storage planning estimator

engineering estimate · not a device quota

Starting assumptions only: 2 KiB blob + 0.5 KiB alias/DB + 1.5 KiB EC certificate chain + 20% overhead. Set certificate bytes to zero for a symmetric key without a chain. The 64-byte trusted-metadata value is intentionally hypothetical; vendors do not expose one common layout.

08 · MCU boot + TEE

Authorize code first. Isolate services second.

Verified boot and a TEE solve different phases of the problem. Anti-rollback closes the “old but valid” hole.

Boot policy decision

all checks must pass
Interview distinction

Three claims, three mechanisms

X.509: this public key is authorized for a constrained identity/purpose under my local root policy.

Verified boot: this exact code/manifest is authorized and new enough to execute.

TEE: this selected runtime code/data remains isolated from the normal environment under the stated hardware and boot assumptions.

09 · DS28C40

A component root of trust—not a magic security chip.

The authenticator protects identity and cryptographic operations. The ECU still owns certificate policy, freshness, enforcement, and bypass resistance.

Authenticate

Challenge + certificate

Prove a provisioned component key answered a fresh challenge. A certificate can carry the P-256 public key and be signed with ECDSA under an OEM chain.

Pair + protect

ECDH then HMAC

Use authenticated ECDH-derived material to establish pairing or protect memory operations. After provisioning, HMAC can support faster recurring authentication when the system lifecycle permits it.

Enforce

Authenticated GPIO

Gate a physical function only after authentication. Analyze alternate traces, MCU pin reconfiguration, fault injection, and compromised-host bypass paths.

Interview trap: “the DS28C40 secures boot” is incomplete. It can contribute an external identity, verification decision, secret, or gated signal. The MCU boot ROM and surrounding hardware must still enforce what executes and prevent bypass.

10 · system design interview

Whiteboard the failure path.

Use seven moves: asset, adversary, boundary, root, transcript, lifecycle, evidence.

  1. Security property
    Name confidentiality, integrity, authenticity, freshness, rollback resistance, or availability.
  2. Adversary
    Network, malicious app, compromised OS, physical attacker, factory insider, or supply-chain substitution?
  3. Trust boundaries
    Draw where plaintext, keys, certificates, counters, and decisions cross.
  4. Protocol transcript
    Write exact inputs, context, encodings, roles, versions, and verification.
  5. Lifecycle
    Provision, use, rotate, revoke, crash, update, recover, decommission.
  6. Catastrophic misuse
    Choose one: nonce reuse, stale LMS state, rollback, invalid chain, KMS outage, or bypass.
  7. Evidence
    Logs, tests, attestation, measurements, negative vectors, and residual risk.
Explain ECDH without hiding behind the paint
Write a(bG)=b(aG), state the discrete-log assumption, validate peer points, explain active MITM, then authenticate and feed the encoded shared result into a transcript-bound KDF. Say explicitly where the paint analogy stops.
Explain ECDSA and recover a key from reused k
Write the signing equation and algebra for recovering k and d. Then cover trusted public-key provenance, encoding/range checks, deterministic nonce generation, constant-time code, and fault leakage.
Why LM-OTS, LMS, and HSS?
Hash assumptions remain attractive under the quantum threat. LM-OTS is one-time; LMS authenticates many LM-OTS public keys with one Merkle root; HSS stacks trees. Spend most of the answer on durable state, concurrency, cloning, backups, and crash recovery.
Does X.509 use ECDSA?
It can. Separate the leaf SPKI algorithm from each issuer’s signature algorithm. Then explain full path validation and proof of private-key possession. On an MCU, define trust anchor, clock, revocation/update, and key-purpose policy.
Design MCU verified boot plus a TEE
Start at immutable ROM and OTP, authenticate a manifest/image before execute, bind target and version, enforce anti-rollback, add power-safe A/B recovery and key rotation, then minimize the secure runtime service API. Explain measured versus verified boot.
What does a DS28C40 do?
Describe a hardware-protected automotive I²C authenticator with ECC, ECDH, HMAC, protected storage, random generation, and authenticated GPIO. Draw challenge/certificate/signature verification and assign enforcement and bypass resistance to the ECU/system.
How much storage do 1,000 StrongBox keys need?
Reject a single universal number. Explain encrypted key blobs versus trusted rollback metadata; measure target-device blob/DB and certificate-chain growth. A planning example at 2 KiB blob + 0.5 KiB metadata + 1.5 KiB cert chain + 20% overhead is about 4.7 MiB outside the secure processor, plus vendor-specific trusted storage. Then load-test key count and operation slots.
